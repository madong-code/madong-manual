## 后端更新（backend/）

### 🔌 插件前置依赖校验（support_app 多依赖）

`info.php` 的 `support_app` 支持 **string 单依赖 / array 多依赖**两种声明模式，安装时逐项校验前置插件是否已安装：

- **声明格式**：`'pay'` / `'pay,portal'` / `['pay', 'portal']` 等价识别；空值或自引用跳过
- **安装阻断**：`PluginInstallService::installCheck()` 逐项检查前置插件 `config/installed.php`，任一未安装即 `overall_status=error` 阻断安装（命令行 `madong-plugin:install` 与后台面板共用链路），错误消息聚合列出全部缺失依赖及标题
- **落库适配**：`sys_plugin.support_app` 由 `varchar(32)` 拓宽至 `varchar(255)`（迁移 `2026_10_10_000001_alter_sys_plugin_support_app.php`），多个依赖逗号分隔存储；`PluginDevelopService` 扫描同步/创建插件时数组归一化为逗号串
- **修复**：前置插件 `info.php` 缺少 `title` 键时依赖检查误报 `Undefined array key "title"`；安装检查失败/警告消息现聚合具体原因（如「CMS内容管理插件的前置插件 pay 还未安装，请先安装」），不再只报错误计数
- 脚手架 `config-info.stub` 补充双模式声明示例

### 🔄 插件开发期前端同步支持额外端点（h5/uniapp）

`madong-plugin:transfer` 的 `resource` / `full` 场景在默认处理 admin/web 之外，支持插件自带的独立前端端点：

- **声明驱动**：插件 `config/info.php` 新增 `template` 键（端点名 => 项目内路径前缀，如 cms 的 `'cms' => 'template/cms/src/plugin'`），与框架 appConfig、`Install.php resolveExtraTarget()` 同一约定，单一事实来源
- **resource 回写**：`{前缀}/{插件名}` → `backend/plugin/{name}/resource/template/{端点}`（clean 镜像）
- **full 对称部署**：`download/{name}/resource/template/{端点}` → `{前缀}/{插件名}`
- **extract 完整性检查**：导出时额外端点资源缺失即告警，提示先执行 `resource`，避免静默产出不完整交付包
- 未声明 `template` 的插件行为零变化（仍只处理 admin/web）；`TransferCommand` 汇总表追加额外端点行

### 📝 cms 插件

- `info.php` 声明 `'support_app' => ['pay']`（付费阅读/会员/打赏经 pay 收单），pay 未安装时安装被明确拦截

### 📦 demo 插件改为用户按需安装

- backend 仓库取消跟踪 `plugin/demo/`（`.gitignore` 白名单移除，仅保留 `plugin/example/`），demo 与其他插件一致走安装包/市场分发，用户按需 `madong-plugin:install demo`
- `template/admin` 移除 demo 运行时副本 `src/plugin/demo/**`（安装 demo 时自动从插件包分发）
- 忽略配置补充：`/.tmp/`、`/tmp-certs/`、`/runtimecerts*.pem`（本地临时目录与运行时证书不入库）

## 升级提示

1. **后端**：`git pull` → `php webman phinx migrate`（`sys_plugin.support_app` 拓宽至 varchar(255)）→ 重启 Webman 进程
2. **插件**：带前置依赖的插件（如 cms 依赖 pay）升级后首次安装需先安装前置插件，否则安装被拦截并提示缺失清单
3. **插件开发者**：插件携带独立前端（h5/uniapp）时，在 `info.php` 的 `template` 键声明端点路径前缀，`madong-plugin:transfer` 的 `resource` / `full` 场景即可自动同步
