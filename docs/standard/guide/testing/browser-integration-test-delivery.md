## 1. 交付目标

本次浏览器联调测试的目标：**验证前台、后台、安装向导三端在目标浏览器与设备上的功能正确性、接口联调一致性、布局兼容性与性能达标情况，为发版提供可量化的准入依据。**

成功判定（四选四满足）：

1. 关键业务链路在全部 P0 浏览器上 100% 通过；
2. 无 S1/S2 缺陷遗留；
3. 性能指标达到第 7 章阈值；
4. 第 9 章交付物齐全、可追溯、可复核。

### 2.1 范围内

| 对象 | 范围 |

- 原生 App、小程序、桌面客户端；

## 5. 待测功能模块与关键业务流程

### 5.1 前台 `source/web`

路由清单（`src/pages/routes.ts`）：

| 编号 | 路由 | 模块 | 关键校验点 |
|---|---|---|---|
| WEB-01 | `/` | 首页 | 站点配置渲染（站点名/页脚/备案/统计）、SSR 首屏、主题切换 |
| WEB-02 | `/search` | 搜索 | 关键词、分页、空结果、移动端输入 |
| WEB-03 | `/member` → `/member/overview` | 会员总览 | 登录态校验、未登录跳转 |
| WEB-04 | `/member/profile` | 个人资料 | 表单校验、头像上传、保存回显 |
| WEB-05 | `/member/settings` | 设置 | 多分组保存、刷新保持 |
| WEB-06 | `/member/third-party` | 第三方绑定 | 绑定/解绑状态、异常提示 |
| WEB-07 | `/member/password` | 修改密码 | 原密码校验、强度规则、改后重新登录 |
| WEB-08 | `/member/points` | 积分 | 列表分页、明细筛选、数值精度 |
| WEB-09 | `/member/balance` | 余额 | 列表分页、金额格式、空态 |
| WEB-10 | `/member/sign` | 签到 | 签到成功/重复签到/连签展示 |
| WEB-11 | 全局布局 | 响应式 | 头部/底部/移动抽屉菜单（`mobile-drawer.vue`）、主题面板、搜索面板 |
| WEB-12 | 路由菜单模式 | 三态 | `NUXT_PUBLIC_ROUTING_MODE=hybrid/backend/frontend` 各模式菜单渲染与跳转 |

关键业务流程（P0）：

1. 未登录访问会员中心 → 跳转登录 → 登录成功回跳；
2. 登录 → 修改资料 → 刷新页面数据保持；
3. 登录 → 签到 → 积分明细出现记录；
4. 移动端：打开抽屉菜单 → 逐级进入会员子页 → 返回；
5. 首页站点配置来自后端 `/api/site/site-config`，页脚版权/备案/统计正确。

### 5.2 后台 `source/admin`

| 编号 | 模块 | 关键校验点 |
|---|---|---|
| ADM-01 | 登录/鉴权 | 账密登录、图形验证码、二维码登录、忘记密码、注册、Token 过期跳转 |
| ADM-02 | 系统-用户 | 增删改查、分配角色、状态切换、导出 |
| ADM-03 | 系统-角色/菜单/部门/岗位 | 权限树勾选保存、返回值回填、数据权限 |
| ADM-04 | 系统-字典/字典项 | 下拉联动、缓存刷新 |
| ADM-05 | 系统-配置 | 分组配置保存、敏感字段掩码 |
| ADM-06 | 系统-文件/回收站 | 上传（图片/文件）、列表预览、恢复/彻底删除 |
| ADM-07 | 会员 | 用户、等级、积分、标签 CRUD 与联动 |
| ADM-08 | 站点 | 站点设置（`/web/site-config`）、菜单、链接；保存后前台生效 |
| ADM-09 | 内容 | 消息、记事、评论审核（通过/驳回） |
| ADM-10 | 运维 | 定时任务、任务日志、网关、系统日志、Redis、服务器监控 |
| ADM-11 | 插件市场 | 列表、安装弹窗、安装进度、失败提示 |
| ADM-12 | 仪表盘/个人中心 | 图表渲染、主题/语言切换、修改密码 |

关键业务流程（P0）：

1. 登录 → 菜单按权限渲染 → 无权限用户看不到且直接访问被拦截；
2. 站点设置保存 → 前台首页刷新后生效（联调闭环，必测）；
3. 角色权限调整 → 重新登录 → 菜单与按钮权限即时生效；
4. 上传文件 → 列表预览 → 前台/后台均可访问该资源 URL。

### 5.3 安装向导（`8500/install`）

| 编号 | 步骤 | 关键校验点 |
|---|---|---|
| INS-01 | 状态检查 `/install/check` | 已安装/未安装判定、`install.lock` 行为 |
| INS-02 | 许可协议 | 未勾选不可下一步 |
| INS-03 | 环境检测 | PHP 扩展、目录权限、缺失项提示 |
| INS-04 | 数据库配置 | 连通性测试、错误密码提示、`.env` 写入 |
| INS-05 | 管理员配置 | 表单校验、非法字符 |
| INS-06 | 执行安装（SSE） | 进度不中断、失败可重试、完成后生成 `install.lock` |
| INS-07 | 完成后跳转 | 跳转后台登录、重复访问提示已安装 |

关键业务流程（P0）：空库 → 全流程一次通过 → 后台可登录 → 前台可访问。

### 5.4 接口联调

| 编号 | 项 | 校验点 |
|---|---|---|
| API-01 | 响应契约 | HTTP 状态与业务 `code` 一致；404 场景不得被误判为成功 |
| API-02 | 鉴权头 | `Authorization`、渠道头、租户头注入正确，401/403 语义正确 |
| API-03 | 分页 | `page/limit`、总数、空页、越界页 |
| API-04 | 错误码 | 参数校验、业务异常、服务异常返回结构化信息 |
| API-05 | 上传 | 大小限制、类型限制、超限提示 |
| API-06 | SSE | 安装进度流不中断、异常可恢复 |
| API-07 | 跨端一致性 | 前台/后台/安装端对同一接口的字段消费一致 |

### 5.5 用例优先级与执行规则

| 级别 | 定义 | 执行要求 |
|---|---|---|
| P0 | 主链路、数据安全、安装部署 | 全部覆盖浏览器 100% 执行 |
| P1 | 主要功能、常见异常 | P0+P1 浏览器 100% 执行 |
| P2 | 次要功能、边缘场景 | 仅 P0 浏览器执行 |

用例编号规范：`TC-<端>-<模块>-<序号>`，端取值 `WEB/ADM/API/INS`。

## 6. 兼容性与响应式要求

### 6.1 断点定义

| 断点 | 宽度 | 前台要求 | 后台要求 |
|---|---|---|---|
| Mobile | < 768px | 完整可用，移动优先 | 不承诺完整功能，但不得白屏/崩溃，需给出友好提示 |
| Tablet | 768 ~ 1199px | 完整可用 | 主流程可用 |
| Desktop | ≥ 1200px | 完整可用 | 完整可用（最小 1366×768） |

### 6.2 判定标准（逐页逐断点检查）

1. 无横向滚动条（除明确设计的可滚动区域）；
2. 无元素重叠、遮挡、截断、溢出；
3. 触控目标 ≥ 44×44px（移动端）；
4. 弹窗/抽屉在视口内完整展示且可关闭；
5. 表格在窄屏下可横向滚动而非撑破布局；
6. 字体、图标、图片不失真、不缺失；
7. 表单键盘弹出后输入框不被完全遮挡（移动端）。

### 6.3 差异容忍度

- 允许：字体渲染微差、1~2px 间距偏差、滚动条样式差异；
- 不允许：布局错乱、功能不可用、内容不可见、交互失效。

## 7. 性能指标

测量条件：本地/内网测试环境，Chrome Lighthouse（Mobile 预设）+ DevTools Performance，每项测 3 次取中位数，记录原始报告。

### 7.1 前台（`source/web`）

| 指标 | 阈值 | 工具 |
|---|---|---|
| LCP | ≤ 2.5s | Lighthouse Mobile |
| CLS | ≤ 0.1 | Lighthouse |
| INP | ≤ 200ms | Lighthouse / Performance |
| TTFB | ≤ 800ms（内网 ≤ 500ms） | DevTools Network |
| 首屏可交互 | ≤ 3s | 手工 + Performance |

### 7.2 后台（`source/admin`）

| 指标 | 阈值 |
|---|---|
| 首屏加载完成 | ≤ 3s |
| 路由切换响应 | ≤ 500ms |
| 100 行表格渲染 | ≤ 1s |
| 弹窗/抽屉打开 | ≤ 300ms |
| 首屏 JS（gzip） | ≤ 1.5MB |

### 7.3 接口（测试环境）

| 项 | 阈值 |
|---|---|
| 普通接口 P95 | ≤ 500ms |
| 分页列表 P95 | ≤ 800ms |
| 10MB 上传 | ≤ 10s |
| SSE 安装进度 | 全程无断流 |

超标即记为性能缺陷，超过阈值 2 倍按 S2 处理。

## 8. 缺陷管理

### 8.1 缺陷类型

`功能缺陷`、`兼容性缺陷`、`响应式/布局缺陷`、`性能缺陷`、`接口契约缺陷`、`交互可用性缺陷`、`国际化/文案缺陷`、`数据一致性缺陷`。

### 8.2 严重等级

| 等级 | 名称 | 判定标准 | 示例 |
|---|---|---|---|
| S1 | 阻断 | 主链路不可用、数据损坏、安装失败、白屏 | 登录失败；首页 500；站点配置接口 404 导致前台无配置 |
| S2 | 严重 | 主要功能失效、某浏览器完全不可用、严重布局错乱、性能超阈 2 倍 | Safari 下会员中心无法提交；后台表格无法滚动查看 |
| S3 | 一般 | 次要功能异常、有替代路径、样式明显偏差、文案错误 | 某浏览器日期格式异常；按钮错位但可点击 |
| S4 | 轻微 | 像素级偏差、体验细节，不影响使用 | 间距 2px 差异；图标对齐微偏 |

### 8.3 缺陷单必填字段

`缺陷编号`（BUG-<模块>-<序号>）、标题、模块、类型、严重级、优先级、发现环境（URL + commit）、浏览器+版本+UA、设备/分辨率、前置条件、复现步骤、期望结果、实际结果、附件（截图/录屏/控制台日志/HAR）、发现人、发现日期、指派人、状态、修复验证记录。

### 8.4 状态流转与时限（建议）

新建 → 已确认 → 修复中 → 待验证 → 已关闭 / 重新打开 / 延期接受。

| 等级 | 确认时限 | 修复时限 |
|---|---|---|
| S1 | 2 小时 | 24 小时 |
| S2 | 4 小时 | 2 个工作日 |
| S3 | 1 个工作日 | 5 个工作日 |
| S4 | 2 个工作日 | 随版本迭代 |

## 12. 验收通过条件（准出）

### 12.1 硬性条件（全部满足）

1. P0 用例在全部 P0 浏览器通过率 = 100%；
2. P1 用例通过率 ≥ 95%，P2 ≥ 90%；
3. S1 = 0，S2 = 0；
4. S3 修复率 ≥ 90%，剩余项有明确规避方案、责任人与修复版本；
5. S4 全部登记，不阻塞发布；
6. 性能第 7 章指标：关键页面 100% 达标，其余页面 ≥ 90% 达标；
7. 安装向导在空库 + P0 浏览器下完整通过，`install.lock` 正常生成；
8. 交付物 D1–D6 齐全，缺陷可回溯到用例与版本 commit。

### 12.2 结论判定

| 结论 | 条件 |
|---|---|
| 通过 | 12.1 全部满足 |
| 有条件通过 | 仅 S3/S4 类遗留，业务方书面接受并明确修复计划 |
| 不通过 | 任一硬性条件不满足 |

### 12.3 复核要求

- 任一条用例结论必须可在同一环境、同一 commit 下复现；
- 缺陷单必须包含复现步骤与附件；
- 性能报告保留原始 Lighthouse 文件，不接受仅填结论。
